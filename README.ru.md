# SSH Storage — инструкция

**Главная идея:** SSH-ключ живёт **только в телефоне**, в защищённом чипе Android Keystore. Компьютер его никогда не получает. При входе на сервер компьютер просит телефон «подписать вход», а вы подтверждаете это на телефоне.

Система состоит из **трёх частей**:

| Часть | Что там | Как ставится |
|---|---|---|
| **1. Компьютер** | программа в `~/.local/share/ssh-storage/` (на NixOS — в модуле), настройки `pc.json` там же (**секретов нет**) | `install.sh` / `.nix` |
| **2. Телефон** (Termux) | программа и список серверов в `~/.ssh-storage/`, SSH-ключ в Android Keystore (извлечь нельзя) | одна команда в Termux |
| **3. Сервер** | в `~/.ssh/authorized_keys`: ключ телефона и резервный ключ | одна команда, компьютер выполняет её сам |
| Ваша бумажка | резервный пароль из 20 символов | — |

Менеджер открывается командой **`ssh-storage`** (на компьютере и на телефоне). Обычная команда `ssh` не меняется.

Порядок первой настройки: **компьютер → телефон → сопряжение → серверы**.

# Часть 1. Компьютер

Файлы проекта:

| Файл | Зачем |
|---|---|
| `sshstore.py` | сама программа (одна на компьютер и телефон) |
| `install.sh` | установщик для Linux и macOS |
| `ssh-storage.nix` | модуль для NixOS / home-manager (программа встроена внутрь) |
| `README.ru.md`, `README.en.md` | эта инструкция на русском и английском |

## Linux и macOS

В папке проекта:

```bash
sh install.sh
```

Поддерживаются Arch и производные (CachyOS, Manjaro, EndeavourOS), Debian/Ubuntu/Mint, Fedora, openSUSE, Alpine, Void и macOS.

Чтобы ничего не сломать, установщик:
- ставит `python3` и ssh-клиент **только если их нет** и **никогда не обновляет систему** (на Arch нет `pacman -Sy`, без частичных обновлений);
- копирует программу в `~/.local/share/ssh-storage/`;
- добавляет команду `ssh-storage` (alias) в `~/.bashrc` / `~/.zshrc` между метками `# >>> ssh-storage >>>` и делает копию `*.ssh-storage.bak`; для fish создаёт `~/.config/fish/functions/ssh-storage.fish`;
- системный `ssh` не трогает, работает от обычного пользователя (sudo спросит только для установки пакетов).

Удаление (данные остаются): `sh install.sh --uninstall`. После установки откройте новый терминал.

## NixOS

```bash
sh install.sh
```

Скрипт скопирует `ssh-storage.nix` в папку с вашим конфигом (спросит, в какую) и сделает `git add` для flake. **Конфиги он не редактирует.** Добавьте в `imports` одну строку:

```nix
./ssh-storage.nix
```

Модуль работает и как модуль NixOS, и как модуль home-manager. Затем `sudo nixos-rebuild switch` (или `home-manager switch`).


Root нужен только для установки. Порты в firewall не открываются: компьютер сам подключается к телефону и серверам.

# Часть 2. Телефон

## 2.1. Установка

Нужны **Termux** и **Termux:API**, оба из F-Droid. Телефон и компьютер должны быть в одной сети Wi-Fi, VPN на телефоне выключен.

1. **Телефон**, в Termux (команду удобно переслать себе в мессенджер):
   ```bash
   pkg install -y python termux-api && python -c "import socket,hashlib,os;c=socket.create_server(('',47232)).accept()[0];c.send(b'R');d=c.makefile('rb').read();print(hashlib.sha256(d).hexdigest()[:16]);input('OK? Enter');p=os.path.expanduser('~/.ssh-storage');os.makedirs(p,0o700,1);f=p+'/sshstore.py';open(f+'.n','wb').write(d);os.replace(f+'.n',f);os.execvp('python',['python',f,'--install'])"
   ```
2. **Компьютер**: `ssh-storage` → **«Сопряжение» → «Установить / обновить приложение на телефоне»** → Enter → выберите телефон.
3. На обоих экранах появится **16-значный код**. Если он совпадает, нажмите Enter на телефоне.
   **Если не совпадает, ничего не нажимайте и закройте Termux**: файл подменили.

При первом запуске телефон сам создаст ключ в Keystore. На главном экране телефона будет написано «ключ SSH: в защищённом чипе».

## Обновление приложения на телефоне

Делается той же установкой (п. 2.1): та же команда в Termux, затем на компьютере «Сопряжение» → «Установить / обновить приложение на телефоне» и сверка 16-значного кода. Заменяется только сама программа. **Сохраняются** сопряжение, список серверов (`~/.ssh-storage/phone.json`) и ключ SSH в Keystore, поэтому настраивать заново ничего не нужно.

Сначала обновите компьютер (`sudo nixos-rebuild switch` или `sh install.sh`): телефон получает программу с компьютера.

## 2.2. Сопряжение и резервный пароль

1. **Телефон**: `ssh-storage` → **«Начать сопряжение»**.
2. **Компьютер**: `ssh-storage` → **«Сопряжение» → «Сопряжение с телефоном»**.
3. При первом сопряжении компьютер покажет **резервный пароль** (20 символов).
   **Запишите его на бумагу** и храните отдельно от телефона, затем введите для проверки. Больше его нигде не будет.
4. Телефон покажет **6 цифр**. Введите их на компьютере.
5. Нажмите `y` на телефоне только после того, как компьютер напишет **«✓ Код верный»**.

## 2.3. Редактирование серверов

Меняются только несекретные данные: название, IP/хост, порт, пользователь. Пароли и способ первого входа **нигде не хранятся**.

- **На телефоне:** `ssh-storage` → **«Серверы»** → выберите сервер → изменить / команда установки / удалить.
- **На компьютере:** телефон в режиме «Ожидать запросы компьютера», на ПК `ssh-storage` → **«Серверы» → «Список серверов»** → выберите сервер → изменить / команда установки / удалить. Список хранится на телефоне, поэтому телефон покажет «было → стало», и изменение сохранится только после `y` на телефоне.

## 2.4. Стереть все данные

- **Компьютер:** `ssh-storage` → **«Специальные возможности» → «Стереть все данные»** → введите `СТЕРЕТЬ`. Удалится `pc.json` (сопряжение и список серверов; секретов там нет). При новом сопряжении создастся **новый** резервный пароль.
- **Телефон:** `ssh-storage` → **«Стереть все данные»**:
  - **«Стереть серверы и сопряжение»** — ключ SSH остаётся, серверы продолжат пускать телефон после нового сопряжения;
  - **«Стереть всё»** — удаляются ключ SSH из Keystore, данные и само приложение. ⚠ **Ни один сервер больше не пустит этот телефон**, доступ возвращается только резервным паролем.

# Часть 3. Сервер

На сервере ничего не устанавливается и настройки sshd не меняются. Скрипт для сервера — это одна команда. Она:

- создаёт `~/.ssh/authorized_keys`, если его нет;
- **заменяет** старый ключ телефона (метка `ssh-storage-phone`) новым;
- **добавляет** резервный ключ, если его там ещё нет;
- **не трогает** остальные ключи;
- в конце печатает `SSH-STORAGE-OK`.

## 3.1. Автоматически (обычный способ)

1. **Телефон**: `ssh-storage` → **«Ожидать запросы компьютера»**.
2. **Компьютер**: `ssh-storage` → **«Серверы» → «Добавить сервер»** → название, IP, порт, пользователь.
3. Сверьте **4-значный код сеанса** на обоих экранах → `y` на телефоне → подтвердите добавление.
4. Компьютер спросит, **как зайти на сервер в первый раз** (ключа телефона там ещё нет):
   - **Пароль сервера** — если на сервере разрешён вход по паролю;
   - **SSH-ключ** — укажите путь к ключу, которым вы входите сейчас (например `~/.ssh/1/vpn`), **или вставьте сам ключ текстом**, начиная со строки `-----BEGIN … PRIVATE KEY-----`. Текст на экране не показывается, ключ кладётся только в оперативную память и стирается сразу после входа;
   - **Автоматически** — обычные ключи из `~/.ssh` и агента.

5. Затем компьютер спросит, что сделать со **старыми ключами** на сервере:
   - **Оставить как есть** — просто добавляется ключ телефона;
   - **Отключить** — все строки в `~/.ssh/authorized_keys` и `authorized_keys2`, кроме ключа телефона и резервного, **закомментируются (не удаляются)**. Это делается **только после проверки входа ключом телефона**: если телефон не пустило, старые ключи не трогаются. Копия: `authorized_keys.ssh-storage.bak`; вернуть всё — на сервере `cp ~/.ssh/authorized_keys.ssh-storage.bak ~/.ssh/authorized_keys`. Другие файлы в `~/.ssh` (config, known_hosts, ключи сервера) не трогаются.

   Компьютер сам выполнит всё на сервере. Этот старый способ нужен **один раз**; после проверки входа через телефон его можно убрать (см. 3.4).

## 3.2. Вручную (если старого входа нет, например есть только веб-консоль хостинга)

1. **Телефон**: `ssh-storage` → **«Серверы» → «+ Добавить вручную»** (или выберите существующий сервер → «показать команду установки»).
2. Телефон покажет команду. Скопируйте её и выполните на сервере под нужным пользователем.
3. Должно появиться `SSH-STORAGE-OK`.

Если автоматическое добавление не прошло, компьютер сам покажет эту же команду.

## 3.3. Подключиться к серверу

1. **Телефон**: `ssh-storage` → **«Ожидать запросы компьютера»**.
2. **Компьютер**: `ssh-storage` → Enter (**«Подключиться к серверу»**).
3. Если код сеанса совпадает, нажмите `y` на телефоне.
4. Выберите сервер. Телефон подпишет вход, и вы на сервере.

На телефоне видно, как прошёл вход:
- **«✓ сервер принял ключ телефона — подпись выдана»** — это телефон знает сам: сервер просит подпись, только если принимает ключ телефона;
- **«✓ вход выполнен, сеанс закрыт»** или **«✗ вход не удался»** — итог после выхода с сервера. Его сообщает компьютер, поэтому это только информация: телефон на её основе ничего не разрешает.

## Меню компьютера и права

```
1 Подключиться к серверу
2 Серверы            — список (изменить / команда установки / удалить), добавить
3 Сопряжение         — сопряжение с телефоном, установить / обновить приложение на телефоне
4 Действия на сервере — проверить права (остальные пункты в разработке)
5 Специальные возможности — восстановление, перенос vault.json, стереть все данные
6 Выход
```

При каждом входе программа узнаёт уровень прав на сервере: **root**, **sudo без пароля**, **sudo с паролем**, **доступ к журналам** (группы `adm`/`systemd-journal`) или **обычный пользователь**. Ничего на сервере не меняется. Уровень виден в списке серверов; пункты «Действий», для которых прав не хватает, показаны с пометкой, что нужно. Это только подсказка для меню, реальные права всегда проверяет сервер. Проверка и сама команда идут через один вход, поэтому телефон подписывает один раз.

Если у пользователя sudo с паролем, проверка (`sudo -n`) может оставить в журнале сервера строку об отказе. Это нормально.

## 3.4. Закрыть старый вход

Пока на сервере остались старые ключи, войти можно и без телефона. После проверки входа через телефон (3.3) выполните на сервере:

```bash
grep -E 'ssh-storage-(phone|recovery)$' ~/.ssh/authorized_keys > ~/.ssh/ak.new && mv ~/.ssh/ak.new ~/.ssh/authorized_keys
```

и на компьютере `ssh-add -D` (очистить агент). Если на сервере включён вход по паролю, он тоже остаётся обходным путём (`PasswordAuthentication no` в sshd — на ваше усмотрение).

# Если потерян или сломан телефон

1. **Компьютер** (подойдёт любой, где есть эта программа): `ssh-storage` → **«Специальные возможности» → «Восстановление по резервному паролю»** → введите пароль.
2. Выберите сервер → **«Подключиться резервным ключом»**. Вы на сервере без телефона.
3. Новый телефон: **установка (2.1) → сопряжение (2.2)**. Затем в «Восстановлении» выберите для каждого сервера **«Привязать сопряжённый телефон»**. Ключ старого телефона на сервере заменится новым, и потерянный телефон больше не войдёт.

# Перенос старых подключений

Если остался старый `vault.json`, в меню компьютера (**«Специальные возможности»**) есть пункт **«Перенести старые подключения»**. Он спросит старый пароль администратора, зайдёт на каждый сервер старым ключом и пропишет ключ телефона. После проверки старый файл `~/.local/share/ssh-storage/vault.json` можно удалить. Исходные ключи в `~/.ssh/` тоже можно убрать, когда всё работает. *(Этот пункт ещё не проверялся.)*

# Что защищено

| Ситуация | Результат |
|---|---|
| **Вирус на компьютере** | Ключа на компьютере нет, украсть нечего. Вирус может только попробовать войти от вашего имени, но для этого нужен `y` на телефоне с совпадающим кодом |
| **Украли файл с компьютера** | В `pc.json` нет секретов |
| **Вирус на телефоне, даже с root** | Ключ из защищённого чипа не извлекается. Вирус может пользоваться им, только пока работает на вашем телефоне |
| **Украли телефон** | Зайдите на серверы резервным паролем и привяжите новый телефон: старый ключ будет удалён |
| **Человек посередине** (кафе) при сопряжении | Его выдаст 6-значный код |
| **Человек посередине** при входе | Устройства проверяют друг друга по ключам, весь трафик зашифрован, плюс код сеанса |
| Чужой запрос **в момент вашего входа** | Код сеанса на телефоне не совпадёт с кодом на компьютере |
| **Подмена при установке** на телефон | Её выдаст 16-значный код проверки |
| **Подбор резервного пароля** | 20 случайных символов: перебор занял бы миллиарды лет |

## Что остаётся (честно)

- **Вирус на компьютере во время вашего сеанса** видит всё, что вы делаете на сервере, потому что это ваш терминал. Ключ он не получит, но сеанс увидит.
- **Нажимать `y` не глядя.** Разрешайте только свои запросы и только при совпадении кода.
- **Резервный пароль — это полный доступ ко всем серверам.** Храните бумажку отдельно от телефона. Пункта «сменить резервный пароль» пока нет: если пароль скомпрометирован, напишите мне.
- Протокол собран из стандартных деталей (X25519, SHA-512, HMAC, ECDSA через Android), но **не проходил независимого аудита**.
- Работа с реальным `termux-keystore` ещё не проверялась на телефоне.
- Установщик проверен на Linux; на macOS и отдельных дистрибутивах вживую не запускался.
- Интерфейс программы пока только на русском.

# Если что-то не работает

- **Телефон не находится**: та же сеть Wi-Fi? VPN выключен? В кафе устройства бывают изолированы друг от друга, тогда введите IP с экрана телефона.
- **«Нет termux-keystore»**: установите Termux:API из F-Droid и выполните `pkg install termux-api`.
- **Добавление сервера не прошло**: выполните на сервере команду, которую покажет компьютер (см. 3.2).
- **На телефоне не работает команда `ssh-storage`**: пишется маленькими буквами через дефис. Если «command not found» — стоит старая версия: переустановите приложение (компьютер → «Сопряжение» → «Установить / обновить приложение на телефоне»), сопряжение и ключ сохранятся. Запасной способ: `python ~/.ssh-storage/sshstore.py`.

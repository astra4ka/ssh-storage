# SSH Storage

SSH-ключ хранится в Android Keystore на телефоне; аппаратная защита зависит от устройства. Компьютер ключа не получает. Когда вы входите на сервер, компьютер просит телефон подписать вход, и вы подтверждаете это на телефоне.

**Экспериментальная версия, не прошедшая независимый аудит.** Реальный Android Keystore, восстановление и изменение настроек VPS требуют проверки на тестовом оборудовании. Не используйте как единственный способ доступа к важным серверам. Ограничения: [SECURITY.md](SECURITY.md).

English version: [README.en.md](README.en.md).

| Где | Что там | Как ставится |
|---|---|---|
| Компьютер | программа и `pc.json` в `~/.local/share/ssh-storage/`. Файл содержит закрытый ключ сопряжения: не публикуйте его | одна команда или `install.sh`, на NixOS модуль `.nix` |
| Телефон (Termux) | программа, закрытый ключ сопряжения и список серверов в `~/.ssh-storage/`, SSH-ключ в Android Keystore | одна команда в Termux |
| Сервер | ключ телефона и резервный ключ в `~/.ssh/authorized_keys` | компьютер прописывает их сам |
| Бумажка | резервный пароль из 20 символов | вы записываете его при сопряжении |

Программа открывается командой `ssh-storage` на компьютере и на телефоне. Обычная команда `ssh` не меняется.

Порядок первой настройки: компьютер, потом телефон, сопряжение и серверы.

## 1. Компьютер

### Установка одной командой (Linux и macOS)

```bash
curl -fsSL https://raw.githubusercontent.com/astra4ka/ssh-storage/main/install.sh | sh
```

Скрипт скачает `sshstore.py`, проверит синтаксис Python и установит программу. Это не проверка подлинности: команда исполняет код из текущей ветки GitHub. Для проверки перед запуском сначала скачайте репозиторий и изучите файлы.

### Установка из папки проекта

```bash
git clone https://github.com/astra4ka/ssh-storage && cd ssh-storage && sh install.sh
```

Поддерживаются Arch и производные (CachyOS, Manjaro, EndeavourOS), Debian, Ubuntu, Mint, Fedora, openSUSE, Alpine, Void и macOS.

Что делает установщик:
- ставит `python3` и ssh-клиент, только если их нет, и никогда не обновляет систему;
- копирует программу в `~/.local/share/ssh-storage/` с правами `600`;
- добавляет команду `ssh-storage` в `~/.bashrc` и `~/.zshrc` между метками `# >>> ssh-storage >>>` и сохраняет копию `*.ssh-storage.bak`. Для fish создаёт `~/.config/fish/functions/ssh-storage.fish`;
- работает от обычного пользователя. Пароль sudo понадобится, только если нужно поставить пакеты.

После установки откройте новый терминал. Удалить программу: `sh install.sh --uninstall`. Ваши данные при этом остаются.

### NixOS

```bash
sh install.sh
```

Скрипт спросит папку с конфигом, скопирует туда `ssh-storage.nix` и сделает `git add` для flake. Сами конфиги он не редактирует. Добавьте в `imports` строку `./ssh-storage.nix` и выполните `sudo nixos-rebuild switch` (или `home-manager switch`).

### Меню компьютера

```
1 Подключиться к серверу
2 Серверы                  список, добавить, новый VPS, массовые действия, перевыпуск ключей, участники
3 Сопряжение               с телефоном, установить или обновить приложение на телефоне
4 Действия на сервере      история, попытки взлома, диагностика, проверка процессов, туннель к веб-панели
5 Специальные возможности  восстановление, перенос vault.json, стереть данные
6 Language / Язык
7 Выход
```

При каждом входе программа узнаёт ваши права на сервере: root, sudo без пароля, sudo с паролем, доступ к журналам или обычный пользователь. Пункты, для которых прав не хватает, помечены. Реальные права всегда проверяет сервер.

## 2. Телефон

### Установка

Нужны Termux и Termux:API, оба из F-Droid. Телефон и компьютер должны быть в одной сети Wi-Fi, VPN на телефоне выключен.

1. На телефоне в Termux выполните (команду удобно переслать себе в мессенджер):
   ```bash
   pkg install -y python termux-api openssh && python -c "import socket,hashlib,os;c=socket.create_server(('',47232)).accept()[0];c.send(b'R');d=c.makefile('rb').read();print(hashlib.sha256(d).hexdigest()[:16]);input('OK? Enter');p=os.path.expanduser('~/.ssh-storage');os.makedirs(p,0o700,1);f=p+'/sshstore.py';open(f+'.n','wb').write(d);os.replace(f+'.n',f);os.execvp('python',['python',f,'--install'])"
   ```
2. На компьютере: `ssh-storage`, «Сопряжение», «Установить / обновить приложение на телефоне», выберите телефон.
3. На обоих экранах появится 16-значный код. Если коды совпадают, нажмите Enter на телефоне. Если не совпадают, ничего не нажимайте и закройте Termux: файл подменили.

При первом запуске телефон создаст ключ в Keystore. Главный экран покажет, сообщает ли Android об аппаратной защите ключа. Отдельный защищённый чип есть не на каждом устройстве.

Пакет `openssh` нужен, чтобы входить на серверы прямо с телефона. Без него остальное работает.

### Обновление

Обновите программу на компьютере (`sh install.sh` или `sudo nixos-rebuild switch`). При следующем сеансе с компьютером телефон сам спросит «Обновить телефон?». Отвечайте «да», только если вы сами обновляли компьютер. Программа передаётся по зашифрованному каналу сопряжения, телефон проверяет её контрольную сумму и не ставит версию старее своей. После сеанса телефон перезапустится с новой версией. Сопряжение, список серверов и ключ сохраняются.

Если на телефоне стоит версия без автообновления (до октября 2026), обновите её один раз вручную той же командой установки.

### Сопряжение и резервный пароль

1. Телефон: `ssh-storage`, «Сопряжение», «Начать сопряжение».
2. Компьютер: `ssh-storage`, «Сопряжение», «Сопряжение с телефоном».
3. При первом сопряжении компьютер спросит, чей это компьютер. На своём компьютере отвечайте «нет» (вы не участник чужой команды). Тогда компьютер покажет резервный пароль из 20 символов. Запишите его на бумагу, храните отдельно от телефона и введите для проверки. Программа его не сохраняет.
4. Телефон покажет 6 цифр. Введите их на компьютере.
5. Нажмите `y` на телефоне только после того, как компьютер напишет «✓ Код верный».

Резервный пароль один на все ваши серверы. При добавлении нового сервера новый пароль не создаётся, туда ставится тот же резервный ключ.

### Меню телефона

- «Ожидать запросы компьютера»: телефон ждёт, когда компьютер попросит подписать вход или изменить список.
- «Серверы»: список серверов. У каждого сервера есть пункты «Подключиться», «Изменить», «Команда установки», «Удалить» и «Туннель к веб-панели». Внизу списка есть «+ Добавить вручную» и, если вы админ команды, «Отозвать участника».
- «Специальные возможности»: журнал одобрений, ваш публичный ключ для админа команды и стирание данных.

## 3. Серверы

### Добавить сервер, на который вы уже входите

1. Телефон: «Ожидать запросы компьютера».
2. Компьютер: «Серверы», «Добавить сервер». Введите название, IP, порт и пользователя.
3. Сверьте 4-значный код сеанса на обоих экранах и нажмите `y` на телефоне.
4. Выберите, как войти на сервер в первый раз: паролем сервера, вашим текущим SSH-ключом (путь к файлу или текст ключа) или автоматически ключами из `~/.ssh`. Текст ключа на экране не показывается и хранится только в оперативной памяти до конца входа.
5. Выберите, что сделать со старыми ключами на сервере. «Оставить» просто добавляет ключ телефона. «Отключить» закомментирует все остальные строки в `authorized_keys`, но только после того, как вход ключом телефона проверен. Копия лежит в `authorized_keys.ssh-storage.bak`.

Программа прописывает ключ телефона и резервный ключ и в конце печатает `SSH-STORAGE-OK`. Настройки sshd при этом не меняются.

### Новый VPS: настроить с нуля

«Серверы», «Новый VPS: настроить с нуля». Есть два варианта.

**Только купил сервер.** Нужны IP, root (или пользователь с sudo) и пароль от хостера. Сервер должен быть на Ubuntu или Debian. Программа:
1. обновляет список пакетов и создаёт вашего пользователя с sudo (пароль sudo вы придумываете сами);
2. прописывает ключ телефона и резервный ключ;
3. включает SSH на старом и новом порту, вход по паролю пока работает;
4. проверяет вход ключом телефона на новый порт;
5. только после этого отключает старый порт, вход под root и вход по паролю.

Если после шага 5 новый вход не подтвердится за 3 минуты, сервер сам вернёт настройки шага 3. Изменения sshd лежат в одном файле `/etc/ssh/sshd_config.d/00-ssh-storage.conf`. Копии старых файлов называются `*.ssh-storage.bak` и не накапливаются: каждый раз перезаписывается одна копия.

**Мне дали личного пользователя на чужом сервере.** Root у вас нет. Программа ставит только ваши ключи и `TERM` в `~/.profile`. Порт, вход root и пароли настраивает владелец сервера.

### Подключиться к серверу

С компьютера: телефон в режиме «Ожидать запросы компьютера», на компьютере `ssh-storage` и Enter, сверьте код сеанса, нажмите `y` на телефоне, выберите сервер и отдельно подтвердите его на телефоне. Повторные подключения при административных действиях требуют повторного подтверждения.

С телефона: «Серверы», выберите сервер, «Подключиться». Компьютер не нужен.

### Туннель к веб-панели (3x-ui и другие)

Так можно открыть панель сервера, не выставляя её в интернет. На компьютере: «Действия на сервере», «Туннель к веб-панели». На телефоне: «Серверы», сервер, «Туннель к веб-панели». Введите порт панели (по умолчанию 2053) и откройте в браузере `http://127.0.0.1:2053/` с путём панели. Ctrl+C закрывает туннель.

После этого в настройках 3x-ui можно разрешить панель только на `127.0.0.1`, и снаружи её видно не будет. Пока туннель открыт, порт доступен и другим программам на этом устройстве, поэтому закрывайте его сразу после работы.

## 4. Командный режим

Подходит для команды до 10 человек. Админ один, у него резервный пароль. Остальные входят только своим телефоном.

### Роли

| Роль | Что может | Для кого |
|---|---|---|
| администратор | sudo и чтение журналов | разработчик, который ставит пакеты и правит конфиги |
| оператор | чтение журналов и только `sudo systemctl restart/reload` | помощник: перезапускает сервисы, смотрит логи, работает в веб-панели через туннель |
| наблюдатель | чтение журналов, без sudo | тот, кто только проверяет |

У каждого участника на сервере свой пользователь и свой ключ. В журналах видно, кто что делал.

Администратору при создании задаётся временный пароль sudo. При первом входе сервер попросит его сменить. Если сервер этого не умеет, программа предупредит, и участника нужно попросить выполнить `passwd`.

### Как подключить участника

1. Участник ставит ту же программу на свой компьютер и телефон и делает сопряжение. На вопрос «Это компьютер участника команды?» он отвечает «да». Резервного пароля у него не будет.
2. Участник присылает вам публичный ключ своего телефона. На телефоне он лежит в «Специальные возможности», «Мой публичный ключ». Это строка, которая начинается с `ecdsa-sha2-nistp256`. Ключ не секретный, его можно отправить в мессенджере.
3. Вы: «Серверы», «Участники серверов», «Добавить участника на серверы». Введите логин, ник, ключ и роль, выберите серверы.

Список участников хранится на вашем телефоне, копия есть на компьютере. После каждого добавления они синхронизируются.

### Отозвать или удалить участника

«Серверы», «Участники серверов», «Отозвать или удалить участника». Выберите участника из списка, затем серверы (Enter выбирает все).

- «Только снять ключи»: ключи участника снимаются, учётка блокируется, открытые сеансы закрываются, sudo снимается. Пользователь и его файлы остаются. Вернуть доступ можно, добавив участника снова.
- «Удалить полностью»: удаляется пользователь вместе с домашней папкой. Для подтверждения нужно ввести ник.

С телефона без компьютера: «Серверы», «Отозвать участника». Это быстрый способ закрыть доступ ночью, если участника взломали. Полное удаление делается только с компьютера.

Ваш пользователь и root никогда не блокируются и не удаляются. Программа трогает только пользователей, которых создала сама: они записаны в реестре `/var/lib/ssh-storage/members`, доступ к которому есть только у root.

### Смена роли и потеря телефона участником

- Сменить роль: добавьте участника снова с новой ролью. При понижении с администратора sudo снимается.
- Участник потерял телефон: отзовите его, затем добавьте снова с ключом нового телефона. Файлы участника сохранятся.

### Что видит участник

У участника скрыты пункты управления командой. Восстановление по резервному паролю ему недоступно: новый доступ даёт админ.

Участник с ролью администратора имеет sudo и технически может сделать на сервере что угодно. Скрытые кнопки этого не ограничивают. Давайте эту роль только тем, кому доверяете.

## 5. Если потерян телефон

Ваш телефон:
1. На любом компьютере с программой: «Специальные возможности», «Восстановление по резервному паролю», введите пароль с бумажки.
2. Выберите сервер, «Подключиться резервным ключом».
3. Новый телефон: установка и сопряжение. Затем в «Восстановлении» для каждого сервера выберите «Привязать сопряжённый телефон» и явно выберите ключ потерянного телефона для отзыва. Программа сначала добавит новый ключ и проверит вход им, затем снимет выбранный старый. Если проверка не пройдёт, старый ключ останется; повторите восстановление. Вариант «Только добавить» не отзывает старые ключи.

Телефон участника: отзовите участника и добавьте его снова с ключом нового телефона.

Если потеряны и телефон, и бумажка, войти на сервер можно только через консоль в панели хостера.

## 6. Безопасность

| Ситуация | Что будет |
|---|---|
| Вирус на компьютере | SSH-ключ телефона не копируется, но вирус может злоупотребить одобренным входом, украсть сеанс или предложить вредоносное обновление |
| Украли `pc.json` | Утёк закрытый ключ сопряжения; отмените сопряжение на телефоне и выполните его заново |
| Вирус на телефоне, особенно с root | Может обойти подтверждения и использовать ключ. Аппаратная защита не делает заражённый телефон безопасным |
| Украли телефон | Войдите резервным паролем и привяжите новый телефон |
| Перехват при сопряжении | Его выдаст 6-значный код |
| Чужой запрос в момент вашего входа | Код сеанса на телефоне не совпадёт с кодом на компьютере |
| Подмена при установке на телефон | Её выдаст 16-значный код |
| Подбор резервного пароля | 20 случайных символов, перебор займёт миллиарды лет |

Телеметрии нет. Программа соединяется только с телефоном в локальной сети (порт 47232), с вашими серверами по SSH и с `127.0.0.1` для туннеля.

Что остаётся:
- Вирус на компьютере во время вашего сеанса может видеть и изменять терминал и команды. Восстановление также вводит резервный пароль на компьютере: заражённый компьютер может его перехватить.
- Телефон проверяет формат SSH-запроса подписи и пользователя, но не удостоверяет адрес сервера: его нет в подписываемых данных. Код сеанса подтверждает канал ПК–телефон, а не безопасность ПК или команды на сервере.
- Нажимайте `y` на телефоне только для своих запросов и только при совпадении кода.
- Резервный пароль даёт доступ ко всем серверам. Если он мог утечь, сделайте «Серверы», «Перевыпуск ключей» с новым резервным ключом.
- Запись команд (auditd) сохраняет команды всех пользователей с аргументами. Если набрать пароль прямо в команде, он попадёт в журнал. Предупредите участников.
- Протокол собран из стандартных частей (X25519, SHA-512, HMAC, ECDSA через Android) и не проходил независимого аудита.

## 7. Вопросы и ответы

**Сколько резервных паролей нужно команде?** Один, у админа. У участников резервного пароля нет, им доступ возвращает админ.

**Что если другой человек при сопряжении ответит «нет, не участник»?** Он получит свой резервный пароль для своих серверов. Ваш пароль не изменится, доступа к вашим серверам он не получит.

**Где хранится список участников?** На вашем телефоне. Копия на компьютере обновляется при каждом добавлении и удалении.

**Можно ли войти на сервер без компьютера?** Да, с телефона: «Серверы», сервер, «Подключиться». Нужен пакет `openssh` в Termux.

**Можно ли пользоваться обычным `ssh`?** Да, программа его не меняет. Но ключа телефона у обычного `ssh` нет.

**Что программа оставляет на сервере?** `authorized_keys` и его копию `.ssh-storage.bak`. После «Нового VPS» файл `/etc/ssh/sshd_config.d/00-ssh-storage.conf`. В командном режиме реестр `/var/lib/ssh-storage/members`. Если включены метрики, файл `~/.ssh-storage-metrics` и строку в crontab. Пункт «Выключить» убирает метрики.

| Проблема | Что сделать |
|---|---|
| Компьютер не находит телефон | Телефон должен быть в режиме «Ожидать запросы компьютера» и не спать. Проверьте, что сеть одна и VPN выключен. В гостевых сетях устройства бывают изолированы, тогда введите IP с экрана телефона |
| «Нет termux-keystore» | Установите Termux:API из F-Droid и выполните `pkg install termux-api` |
| «Нет ssh: выполните pkg install openssh» | Выполните `pkg install openssh` в Termux |
| «не нашёл SSH-сервер на этом порту» | Проверьте IP и порт. Порт может быть закрыт файрволом хостера |
| Добавление сервера не прошло | Выполните на сервере команду, которую покажет компьютер, или возьмите её на телефоне: сервер, «Команда установки» |
| «Новый VPS» остановился на шаге 1–3 | Вход по паролю остался рабочим. Исправьте причину из сообщения и повторите |
| После «Нового VPS» нет входа | Подождите 3 минуты: сервер сам вернёт старый порт и вход по паролю |
| Участник: «пользователь уже есть и это не участник» | Этот логин на сервере занят не вашим участником. Выберите другой логин |
| Отзыв: «не выполнено» | Сервер недоступен или вы не ввели пароль sudo. Повторите для этого сервера |
| `ssh-storage: command not found` на компьютере | Откройте новый терминал. Запасной способ: `python3 ~/.local/share/ssh-storage/sshstore.py` |
| `ssh-storage: command not found` на телефоне | Переустановите приложение (раздел 2). Запасной способ: `python ~/.ssh-storage/sshstore.py` |
| Установщик: «Set your GitHub name in REPO_RAW» | Замените `OWNER` в адресе на имя аккаунта или запустите с `SSH_STORAGE_RAW=https://raw.githubusercontent.com/ИМЯ/ssh-storage/main` |
| Установщик: «sshstore.py is damaged» | Файл скачался не полностью. Запустите установку ещё раз |

Ограничения: работа с настоящим `termux-keystore` и командный режим ещё не проверялись на живых устройствах и серверах. Установщик проверен на Linux, на macOS вживую не запускался. По умолчанию интерфейс английский: русский включается в главном меню пунктом «Language / Язык» отдельно на компьютере и на телефоне. Выбор хранится в `pc.json` / `phone.json` и не сбрасывается при перезапуске, сопряжении и обновлении. Пункт «Стереть все данные» удаляет и сохранённый язык.

## Проверки для разработчиков

Без сторонних Python-зависимостей: `python3 -m unittest discover -s tests -v` и `sh -n install.sh`. Тесты используют временные каталоги и заглушки для телефона, не подключаются к вашим серверам. Это не заменяет проверку настоящего SSH-входа и Android Keystore.

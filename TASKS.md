# SSH Storage — задачи

Две версии на общем ядре:
- **Small** — личное использование и маленькая команда (до 5 человек). Каждый ключ прописан на серверах напрямую (`authorized_keys`).
- **Team** — команда 10–20+ человек. Серверы доверяют удостоверяющему центру (SSH CA), участники получают короткие сертификаты с ролью. Ключ CA — в Keystore телефона админа.

Решения, уже принятые:
- Root по SSH заблокирован; вход обычным пользователем, root — только `sudo`/`su` внутри сервера. Программа это не меняет.
- Пароли (серверов, sudo) нигде не хранятся; способ первого входа спрашивается только при добавлении.
- Права ограничивает сервер (пользователи, группы, sudo, ограничения ключей); проверка прав в программе — только для удобства меню.
- Запись команд — через `auditd` (изменение сервера, только с sudo, с копией настроек и откатом).
- Любой перевыпуск ключей — с подтверждением на ПК (слово) и на телефоне, с предупреждением, кто потеряет доступ.
- Каждое опасное действие — отдельный вход телефоном с понятной причиной на экране телефона.
- Приватность участников: личные данные других пользователей (IP входа и т.п.) не показываются. Сомнительные данные — сначала обсудить.

Обозначения: `[ ]` не начато, `[~]` в работе, `[x]` готово, `[—]` отказались. **S** — нужно в Small, **T** — в Team.

## Этап 1. Серверы (S, T)

- [x] 1.1 Список → изменить / команда установки / перевыпустить ключи / удалить. (перевыпуск — пункт-заглушка до 1.5; добавлено «Обновить ключи на сервере»)
- [x] 1.2 Массовое добавление: из файла (`имя хост порт пользователь`), из `~/.ssh/config`, вставкой списка; один сеанс с телефоном; способ первого входа — общий или для каждого; итоговый отчёт (добавлено / нет и почему).
- [x] 1.3 Массовое удаление: выбор номерами через запятую/пробел, подтверждение; режимы «только из списка» / «из списка + снять ключи с сервера».
- [x] 1.4 Режим ключей — решено: один ключ на одно устройство (ключ телефона общий для всех серверов, резервный — из одного 20-символьного пароля). Так уже работает, отдельный режим не нужен.
- [x] 1.5 Перевыпуск ключей (один сервер и массово): какой ключ (телефона / резервный / оба), заменить или добавить; сводка изменений; подтверждение словом на ПК и `y` на телефоне; предупреждения:
  - чужие ключи на сервере и выбрано «затереть» → «⚠ участники … потеряют доступ»;
  - перевыпуск резервного → «старый резервный пароль перестанет работать».
- [x] 1.6 Проверка корректности ввода хоста/порта и доступности сервера до входа.

## Этап 2. Действия на сервере (S, T)

- [x] 2.1 История без изменений сервера: входы (кто, когда, ключ → ник; без IP), sudo-команды, su, пакеты (apt/dnf/pacman), изменения в `/etc`.
- [x] 2.2 `auditd`: включить / выключить (sudo, копия настроек, откат); история команд с исходным пользователем входа (login uid) даже после `sudo -i`/`su`.
- [x] 2.3 Попытки взлома (только чтение, обычный сеанс — не опасное действие): IP показывать только для ≥5 неудачных входов и для входов под несуществующим логином; единичные ошибки участников — без IP.
- [x] 2.4 Смены пользователя (su/sudo) — с исходным пользователем. — покрыто: su и sudo — в «Истории» (2.1), исходный пользователь после sudo -i/su — в «Записи команд auditd» (2.2).
- [x] 2.5 Диагностика — упавшие сервисы и ошибки журнала, нумерованный список; перезапустить / убить по номерам через запятую; защита: sshd, PID 1, свой сеанс не предлагаются; сначала SIGTERM, SIGKILL отдельным выбором; подтверждение списком.
- [x] 2.6 Проверка на зачатки неисправностей: диск и inode, память/swap/OOM, рост ошибок, read-only ФС, время, SSL-сертификаты, обновления безопасности, нагрузка. Быстрая и полная проверка.
- [x] 2.7 Перезагрузка: подтверждение на телефоне, ожидание, сообщение «сервер снова в сети».

## Этап 3S. Версия Small (до 5 человек)

- [x] S.1 Командный режим: свой Unix-пользователь на человека (помощь в создании через sudo, с подтверждением).
- [x] S.2 «Отключить старые ключи» затрагивает только свои ключи; чужие — только с явным выбором и предупреждением.
- [x] S.3 Резервный пароль: в командном режиме — только у админа; остальные восстанавливаются через админа.
- [x] S.4 Добавить участника на серверы: его публичный ключ + ник → выбранные серверы.
- [x] S.5 Отозвать участника со всех серверов одной операцией, отчёт (где удалено / где сервер недоступен).
- [x] S.6 Роли с реальными правами: администратор — sudo (временный пароль, смена при первом входе) и журналы; оператор — журналы и `sudo systemctl restart/reload`; наблюдатель — журналы. Смена роли повторным добавлением (понижение снимает sudo). Проверка, что sudo реально работает (Arch/wheel).
- [x] S.7 Отзыв «жёсткий»: снять ключи, заблокировать учётку, закрыть сеансы, снять sudo. Повторная выдача после отзыва (потеря телефона). Выбор серверов при отзыве и удалении.
- [x] S.8 Полное удаление участника (пользователь + папка), в т.ч. уже отозванного. Реестр `/var/lib/ssh-storage/members` (только root): чей это пользователь, даже если метку ключа стёрли; снимается только своя блокировка.
- [x] S.9 Список участников: главный на телефоне, копия на ПК, синхронизация при добавлении/удалении. Выбор номером при отзыве.
- [x] S.10 Телефон без ПК: вход на сервер, туннель, отзыв участника (снять ключи), «Мой публичный ключ» для админа.
- [x] S.11 Участнику (без резервного пароля) скрыты: управление участниками, «Новый VPS», восстановление.
- [x] S.12 Туннель к веб-панели (3x-ui и др.) с ПК и телефона, с предупреждением о локальном доступе. Предупреждение перед включением auditd.
- [x] S.13 «Новый VPS: настроить с нуля»: только купленный (пользователь с sudo, ключи, новый порт, root и пароли выключить, откат через 3 мин) и личный пользователь на чужом сервере.
- [x] S.15 Автообновление телефона с ПК: после разрешения сеанса ПК предлагает свою версию, телефон спрашивает, получает файл частями, проверяет sha256 и синтаксис, не ставит версию старее (`VERSION`), перезапускается. Сообщения version / update_part / update_done не менять — по ним обновляются старые телефоны. При выпуске поднимать `VERSION`.
- [x] S.14 Alpine/busybox: создание участника без usermod/gpasswd/passwd -e, без пустого пароля.
